Query-aware 推荐链路速查

一句话：History 管长期偏好，Query 管眼前需求；先各自找 500 家并全部保住，再让历史模型和当前语义共同粗排，最后只对 30 家做昂贵精排。

总流程

EffectiveSessionRequest → History 五路 Top-500 + Query 四路 Top-500 → 受保护并集 → 硬排除 → 32维 LambdaMART + Query信号 → 粗排 → Top-30 Cross-Encoder → Top-5

History 五路

路线人话解释关键计算
Quality大家普遍认为好、且评论证据足的店0.8×贝叶斯评分 + 0.2×对数人气
Category用户过去爱去哪些细分类餐厅0.7×该类平均评分 + 0.3×访问频率
Text商家描述像不像用户好评文本，并避开差评文本0.5 + 0.5×正向TF-IDF相似度 − 0.5×负向相似度
Location离用户历史活动中心近不近exp(−距离/10km)
Item-KNN和用户喜欢过的店，经常被相似人群共同喜欢的店时点安全共现相似度 + 支持度收缩

五路各取最多 500，再用 Σ 1/(60+路线名次) 合成 History Top-500。

Query 四路

路线人话解释注意点
Category用户现在明确要的菜系按目标类别交集比例排序
Embedding整句话的意思和商家静态文档像不像本地 Qwen3 双塔，适合大范围初筛
Aspect评论证据是否支持“安静、约会、停车”等要求未知保持中性，不伪装成不满足
Location离本次请求位置近不近不同于 History 的历史活动中心

四路当前权重均为 1，用同样的 RRF 合成 Query Top-500。硬类别、距离、价格和硬 Aspect 在召回前过滤。

冻结粗排公式

QuerySignal = 0.8×Query召回百分位 + 0.2×并集Embedding百分位
CoarseScore = 0.5×LambdaMART百分位 + 0.5×QuerySignal

LambdaMART 使用最终消融选中的 32 维：13 个基础召回特征、7 个 Item-KNN、7 个用户画像、5 个商家画像。完整池原有 36 维，但删除了 4 个不稳定的任务级 Review-Aspect 匹配特征。

Top-30 精排

SemanticScore = 0.4×Embedding + 0.5×CrossEncoder + 0.1×结构化条件匹配

Cross-Encoder 让 Query 和商家信息一起编码，判断更细但更贵，所以只处理粗排前 30。策略还限制最多上移 5 位、下移 3 位，并保护粗排 Top-3，避免一次语义误判颠覆整张榜单。

面试口诀：五路历史看“你以前是谁”，四路 Query 看“你今天要什么”；并集保证两边不丢人，LambdaMART 做大范围筛选，Cross-Encoder 做小范围精修。
