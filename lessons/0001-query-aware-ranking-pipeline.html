从一句请求到五家餐厅

目标：能用一个具体例子，讲清 History、Query、受保护并集、LambdaMART 和 Top-30 精排分别干了什么。

贯穿示例：“我今天想在市政厅 5 公里内找一家安静、适合约会的牛排馆，别再推荐上次那家。”

第一幕：先把话变成可执行请求

系统保留用户原话，同时从会话记忆中取出仍然有效的偏好、硬条件和已拒绝商家，生成 EffectiveSessionRequest。受约束 Router 只从代码给出的合法动作中选出 GET_QUERY_AWARE_RANKING，它不生成商家 ID，也不亲自排序。

第二幕：两支搜索队同时出发

History 队

不看“今天”这句话，主要根据用户截止当前的历史行为，从 Quality、Category、Text、Location、Item-KNN 五个角度各找最多 500 家，再用名次融合得到 History Top-500。

Query 队

围绕“牛排、5公里、安静、约会”搜索当时已经存在的商家。先执行硬过滤，再从 Category、Embedding、Aspect、Location 四个角度各找最多 500 家，融合成 Query Top-500。

第三幕：不是投票淘汰，而是先把两边都保住

系统取两份 Top-500 的集合并集，最多 1000 家。只在 Query 队出现的店不会因为没有历史匹配而被提前扔掉；只在 History 队出现的店也不会因为一句 Query 表达不完整而消失。Query 路线判定违反硬条件的商家，以及 Session 中已拒绝的商家，会从整个并集中删除，所以 History 不能把违规商家重新带回来。

第四幕：LambdaMART 给历史与可靠性打底

冻结的 LambdaMART 对并集里的每家店计算分数。最终线上模型使用 32 维特征，包括召回名次与各路线分数、Item-KNN、用户画像和商家画像。Query-only 商家缺少 History 路线证据时用缺失标记和默认值表示，但仍然可以凭商家画像和后续 Query 信号继续竞争。

第五幕：把“过去的你”和“今天的你”合成一张粗排榜

系统还会对完整并集统一计算一次 Embedding，使 History-only 商家也拥有当前 Query 语义分。随后把 LambdaMART 名次、Query 召回名次和 Embedding 名次都变成 0～1 百分位，再按冻结权重融合。

QuerySignal = 0.8×Query召回百分位 + 0.2×Embedding百分位
CoarseScore = 0.5×LambdaMART百分位 + 0.5×QuerySignal

第六幕：只请昂贵专家复核前 30 家

Embedding 像先分别阅读 Query 和商家资料，再比较两个向量，便宜、适合大范围筛选。Cross-Encoder 则把 Query 和商家资料放在一起逐词判断，更细但更慢。因此系统只把粗排 Top-30 交给 Qwen3-Reranker。

精排分数同时考虑 Embedding、Cross-Encoder 和结构化条件证据，并限制名次移动、保护粗排 Top-3。最终保留完整排序，内部取 Top-10，再读取前 5 家详情展示给用户。

自测

  1. 为什么这里取并集，而不是交集？
  2. History Location 与 Query Location 的中心点分别来自哪里？
  3. 为什么 Query 召回里做过 Embedding，并集阶段还要再做一次？
  4. 正确商家如果粗排第 40，Cross-Encoder 能不能把它排进 Top-5？
