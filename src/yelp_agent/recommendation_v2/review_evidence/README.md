# 评论证据排序

这个目录负责一件完整的事：接住四路融合后的当前要求和硬筛结果，为每条软偏好取得可排序的满足程度和真实证据，重新排出前五。固定14项读取500家离线画像；固定14项之外的自由要求才临时查评论。

## 实际顺序

1. `segmenter.py` 按完整句子切评论。相邻片段重复上一片段末尾的一句；只有单句本身超过 900 字时才在词语边界继续拆；不限制一条长评论最多产生几个片段。
2. `builder.py` 生成片段和 1024 维本地向量。文字完全没变的片段会复用旧向量，只重新计算新增或改变的片段。
3. `offline_aspects.py` 批量读取硬筛商家的固定14项分数。按用户想要的高低方向转换后，再按证据充分程度向0.5收缩；不可用于排序的项按未知0.5处理。高低程度代表评论会随用户方向转换成正反证据。
4. 只有自由要求才进入后续评论检索。`qdrant_store.py` 把同一份片段同时建成“按意思找”和“按关键词找”两套索引。检索条件里直接带硬筛后的商家编号和本轮请求时间上限，不会查到候选范围以外或未来的评论；用户画像生成时间不再限制评论范围。
5. 自由要求的检索说法由需求融合模型在同一次调用中生成。每项生成2条正面说法和2条反面说法。单问题实验显示，从2条增加到4～5条没有继续提高召回，却把查询耗时约翻倍，因此先选2条。
6. `retrieval.py` 一次编码本轮全部自由要求说法。“按意思找”和“按关键词找”同时执行，再按两边各自的名次合并。
7. 合并查询结果后，每个商家每条自由要求分别保留正面最多15条、反面最多15条候选；同一评论的多个片段合并回原评论。
8. P至少0.60且比N高至少0.05时判为正面；反面同理；其余算模糊评论，不参与得分。
9. `scoring.py` 为自由要求保留正面前五和反面前五，按相关程度、时间和数量聚合；没有证据时为0.5。
10. `ranker.py` 把离线固定项、动态自由要求和商家结构化事实放回同一优先级顺序。每项先压成五个档位，再逐层比较：

   ```text
   第一优先级档位
   → 同档才比较第二优先级档位
   → 继续比较后续偏好档位
   → 全部同档才按商家评分、评论数、距离兜底
   ```

   “证据不足”和“一般”都放在中间档：不能因为一条含糊评论冒充满足，也不能把没有证据误判成不满足。旧的加权偏好分和最终分仍留在结果中供新旧实验核对，但不再决定实际名次。

11. 最终只返回前五。完整结果保留原评论；最终回答模型只读取通俗满足档位以及每家最多两条代表性正反证据。

## 主要文件

- `schema.py`：评论召回、正反证据、商家偏好分和最终 Top5 的固定结构。
- `segmenter.py`：评论切分规则。
- `builder.py`：生成新片段和本地向量。
- `qdrant_store.py`：Qdrant 双索引导入、商家范围过滤、两路并行查询和名次融合。
- `segment_vectors.py`：按 Qdrant 点编号从本地向量文件一次读取不同片段向量。
- `full_reviews.py`：根据评论编号还原完整原评论。
- `offline_aspects.py`：读取固定14项离线分数，处理用户方向、证据充分程度和代表评论。
- `descriptions.py`：固定 14 种说法，以及离线或旧调用方的兼容入口；真实工作流直接使用融合结果。
- `retrieval.py`：P/N 计算、每家召回上限、方向判定和评论去重。
- `scoring.py`：相关程度、时间、数量和正反证据聚合。
- `ranker.py`：按偏好优先级逐层比较，并用商家基础事实稳定处理同档商家。
- `runtime.py`：固定14项不会启动向量环境；只有出现自由要求时才延迟连接本地Qdrant和向量模型。
- `steak_real_api_demo.py`：真实执行“我想吃牛排”并保存完整结果。
- `cross_encoder_judge.py`：第二版实验，先判断相关，再尝试区分正反。
- `qwen_five_class.py`：第三版实验的单一入口，只返回五类之一。
- `qwen_five_class_worker.py`：让 Qwen2.5-3B 常驻显卡并批量执行五选一。

## 本地数据位置

所有新运行数据仍在 `recommendation_v2` 内：

```text
recommendation_v2/data/review_evidence/v1/
  segments/                 新评论片段
  index/                    本地向量和生成记录
  runs/                     真实查询完整结果

recommendation_v2/data/qdrant/v1/
  Qdrant 持久化数据
```

这些文件体积很大，可以由代码重新生成，因此不会加入普通 Git。

## 当前参数的含义

- 0.55：只负责粗召回。低于它的评论连候选都不是。
- 0.60：当前接受门槛。真实召回审计显示，这套本地模型的相关评论主要落在 0.60～0.74；达到它才有资格成为正面或反面证据。
- 0.05：正反差值门槛。防止一条同时像正面又像反面的评论被硬判方向。
- 60：两路名次融合的平滑值。它只负责把两条召回路线合起来，不参与评论方向和最终商家得分。
- 730 天：时间权重减半周期。评价越新影响越大，但旧评价不会突然归零。
- 5 条：正面或反面达到五条时，数量可靠度达到满值。

这几个数都是当前工程起点，不是假装绝对正确。后续要用人工标好的评论和推荐案例分别校准召回门槛、接受门槛、差值以及五档阈值。
