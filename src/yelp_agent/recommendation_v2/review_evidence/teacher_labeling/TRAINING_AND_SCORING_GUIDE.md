# 14 种评论特征：训练标签与商家打分说明

这份说明解决两个容易混淆的问题：

1. 教师模型和学生模型到底需要判断什么；
2. 模型给出的“相关程度”和“五档强度”以后怎样进入商家打分。

## 一、每条训练样本只判断两件事

模型输入是一种指定特征及一段真实评论。模型输出：

```json
{
  "relevance": 3,
  "strength": 1
}
```

### 相关程度 `relevance`

相关程度只回答：**这段评论是否真的在谈当前特征？** 它不表示好坏。

| 数值 | 含义 | 后续用途 |
|---:|---|---|
| 0 | 完全没有谈到 | 丢弃；强度必须为空 |
| 1 | 只能间接、勉强推测 | 弱证据；不能单独支撑强结论 |
| 2 | 明确谈到，但描述较短或上下文有限 | 可用证据 |
| 3 | 明确谈到，而且描述清楚、充分 | 强证据 |

### 五档强度 `strength`

五档强度回答：**评论所描述的商家，在当前特征的客观刻度上处于什么位置？**

| 数值 | 通用含义 |
|---:|---|
| 0 | 这个特征的最低端 |
| 1 | 比较低 |
| 2 | 中等、普通、好坏混合或取决于条件 |
| 3 | 比较高 |
| 4 | 这个特征的最高端 |

`strength` 不是评论星级，不是证据可靠度，也不是“是否满足当前用户”。例如，“非常吵，必须喊着说话”是一条非常明确的安静程度证据，它的结果应当是：

```json
{
  "relevance": 3,
  "strength": 0
}
```

评论完全没有谈到当前特征时：

```json
{
  "relevance": 0,
  "strength": null
}
```

## 二、每种特征的数值方向

“数值越高”不是统一表示“越好”，而是表示越接近该特征定义的高端。

| 特征 | 0 档代表 | 4 档代表 | 数值越高代表 |
|---|---|---|---|
| 菜品质量 | 很差、难吃或不新鲜 | 非常出色 | 菜品越好 |
| 服务质量 | 服务很差 | 服务非常出色 | 服务越好 |
| 性价比 | 非常不值 | 非常物超所值 | 越划算 |
| 安静程度 | 非常吵 | 非常安静 | 越安静 |
| 拥挤程度 | 完全不拥挤 | 非常拥挤 | 越拥挤 |
| 等位时间 | 无需等待 | 等待非常久 | 等得越久 |
| 菜品分量 | 分量非常小 | 分量非常大 | 分量越大 |
| 停车便利度 | 几乎无法停车 | 停车非常方便 | 越容易停车 |
| 宠物友好度 | 禁止或排斥宠物 | 提供明确宠物便利 | 越宠物友好 |
| 家庭儿童友好度 | 很不适合儿童 | 有完善的儿童便利 | 越适合家庭儿童 |
| 约会适合度 | 很不适合约会 | 非常适合约会或纪念日 | 越适合约会 |
| 多人聚餐适合度 | 很不适合多人 | 非常适合大型聚餐 | 越适合多人 |
| 辣度 | 完全不辣 | 极辣 | 越辣 |
| 清洁程度 | 非常脏 | 非常干净 | 越干净 |

因此，不能在排序时简单地把所有特征都按“数值越高越优先”处理：

- 用户想要安静：安静程度越高越匹配；
- 用户不想拥挤：拥挤程度越低越匹配；
- 用户不想等位：等位时间越低越匹配；
- 用户想吃清淡：辣度越低越匹配；
- 用户想吃很辣：辣度越高越匹配。

## 三、训练数据怎样使用

教师模型和微调后的学生模型必须看到相同的输入字段，并输出相同的两个字段。训练时：

- `model_input` 是学生模型输入；
- `model_output` 是教师给出的训练答案；
- 候选文件外层的评论编号、商家编号、星级、点赞数、语义相似度和挑选桶只用于追溯，不能放进学生模型输入；
- `selection_relevance` 和 `selection_strength` 是旧程序为了挑选不同样本做的粗略分桶，不是训练答案；
- 正式训练只能使用教师输出，人工复核结果可以覆盖教师输出。

数据拆分必须按评论编号进行。同一条评论的不同片段不能一部分进入训练集、另一部分进入验证集，否则验证结果会虚高。推荐先按评论编号划分为：

- 训练集 80%；
- 验证集 10%；
- 最终测试集 10%。

最终测试集应当人工检查，不能只把教师模型输出当成绝对正确答案。

## 四、评论强度怎样变成商家特征分

首先把五档强度换算成 0～1：

```text
评论强度值 = strength / 4
```

即 0、0.25、0.5、0.75、1.0。然后只让真正相关的评论参与商家聚合：

```text
相关程度权重：
0 → 0
1 → 0.25
2 → 0.65
3 → 1.00
```

这是第一版建议值，后续应通过人工验证集校准。单条评论最终权重还需要乘以：

- 时间权重：越新的评论影响越大；
- `useful` 轻微加权：有用票较多可以略微增加权重，但必须设置上限；
- `cool` 暂时不使用；
- 同一用户对同一商家的重复评论需要去重或限制总权重。

单条评论权重大致为：

```text
证据权重 = 相关程度权重 × 时间权重 × 有用票轻微权重
```

商家在某个特征上的原始程度，是全部有效评论强度的加权平均：

```text
商家特征程度 = Σ(评论强度值 × 证据权重) / Σ证据权重
```

商家不能只保存一个程度分，还需要同时保存：

- 有效评论数量；
- 证据总权重；
- 证据充分程度；
- 评论之间的争议程度；
- 最有代表性的高端、低端和条件性证据。

没有有效证据时应标记为“未知”，不能强行记成 0.5。`0.5` 表示评论确实说明它处在中间程度，而“未知”表示没有足够评论可以判断，两者不是一回事。

## 五、商家特征分怎样与用户要求匹配

商家特征程度和用户需要是两件事。先得到商家的客观程度，再根据用户本轮要求计算匹配程度：

- 用户要“越高越好”：商家程度越高，匹配越高；
- 用户要“越低越好”：使用 `1 - 商家程度`；
- 用户要某个中间档位：根据商家程度和目标档位的距离计算匹配；
- 商家证据不足时降低其排序影响，同时向用户明确说明不确定；
- 商家评论争议很大时不能只展示正面评论，必须同时返回主要风险。

例如商家辣度为 0.9：

- 对“想吃特别辣”的用户接近满分；
- 对“想吃清淡”的用户接近 0.1；
- 对“只要微辣”的用户也不应排在前面。

最终排序使用的是“商家客观程度与用户目标的匹配程度”，而不是直接使用五档强度。

## 六、当前数据量的正确理解

第一批共有 630 条，即每种特征 45 条。它足够验证输入输出格式和跑通训练流程，但对 30 亿参数模型的稳定微调偏少。

第二批已经完成14种特征每种153条，总量2142条。其中1733条具有五档强度，409条被教师判断为与指定特征无关。这个规模适合做第一轮QLoRA基线，但仍不能只看训练损失。是否够用最终取决于：

- 14 种特征是否都有足够样本；
- 相关程度和五档强度是否严重偏科；
- 否定、转折、条件限制和正反混合评论是否充足；
- 独立人工测试集上的相关判断和强度判断是否达到要求。

如果某些档位仍然只有个位数，即使总数超过 2,000，也要针对缺少的档位继续补数据，而不是盲目增加已经很多的档位。

第二批整体五档分布如下：

| 教师答案 | 数量 |
|---|---:|
| 强度0 | 413 |
| 强度1 | 402 |
| 强度2 | 193 |
| 强度3 | 340 |
| 强度4 | 385 |
| 无关，强度为空 | 409 |

整体数量不等于每种特征内部都均衡。正式制作LLaMA-Factory训练集前，必须读取审计文件逐类检查；尤其要关注某种特征的某一档是否只有少量样本。
