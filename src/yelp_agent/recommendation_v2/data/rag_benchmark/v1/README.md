# 评论召回评测数据 v1

## 单问题全量评论评测

正式生成结果位于 `cases/rag_authentic_szechuan_0001/`。

这套数据针对“费城唐人街中心 300 米以内的川菜是否地道”这一个真实问题，先用现有硬条件筛出 4 家商户，再把这 4 家商户的 893 条完整评论全部交给 Claude Code 中配置的 GLM-5.1 逐条判断，没有先用评论检索挑选候选。

- 商户：Delightful Garden、Bai Wei、E Mei Restaurant、Tango。
- 完整评论：893 条，每条恰好出现一次。
- 标签：正面 270 条、反面 47 条、正反都有 60 条、无法判断 42 条、无关 474 条。
- 模型调用：24 次，包含失败、重试和拆分调用。
- 词元：输入 240,964，输出 163,094，思考词元 0。
- Claude Code 报告的费用估算：5.340986 美元。

目录内容：

- `inputs/`：每次标注实际使用的完整输入。
- `raw_outputs/`：Claude Code 返回的原始包装，失败和重试也保留。
- `hidden/all_review_labels.jsonl`：893 条逐评论标签和逐字证据。
- `audit/`：当前评论检索结果和漏召回明细。
- `report.json`、`summary.md`：本次运行统计和召回对比。

这些标签是“GLM 生成 + 程序严格校验”的教师标签，不是人工金标准。程序确认了评论编号、商户编号、条数、证据原文位置和数据结构，但最终用于论文结论前仍应进行人工抽检。

## 逆向评论召回评测集

正式生成结果位于 `inverse_generation/inverse_v1_0002/`。

## 当前内容

- `drafts/inverse_cases.jsonl`：76 条可以直接读取的评测草稿。
- `accepted/`：16 个批次分别通过程序检查后的结果。
- `inputs/`：发送给生成模型的真实评论候选，用于复查生成依据。
- `raw_outputs/`：18 次模型原始返回，用于追查失败和重试原因。
- `generation_report.json`：数量、方向、耗时和词元统计。
- `manual_review_queue.json`：程序检查无法代替人工语义判断的复核项。

## 数量

- 14 种固定需求：每种 4 条，共 56 条；每种包含 2 条正面证据和 2 条反面证据。
- 长尾需求：20 条。
- 总计：76 条；正面 38 条，反面 38 条。
- 76 条样本分别来自 76 条不同真实评论，问题文本也没有完全重复。

## 正确性边界

当前状态是“GLM 生成 + 程序验证”，不是“人工确认的最终正确答案”。程序已经确认：

1. 评论编号来自本批真实候选；
2. 证据是对应完整评论中的逐字连续原文；
3. 同一评论没有被重复使用；
4. 固定需求的正反数量符合要求；
5. 证据能够落回一个真实评论片段。

程序不能完全代替人判断证据含义是否足够强。正式作为论文或最终系统的标准答案前，应处理 `manual_review_queue.json`，再把确认状态升级为人工复核通过。

## 生成模型

通过 Claude Code 的 Haiku 入口调用 `GLM-5.3-Flash[1m]`。为了兼容当前 Z.AI 接口，本次生成临时使用官方验证过的 Claude Code 2.0.14，没有覆盖本机日常使用的新版 Claude Code。
