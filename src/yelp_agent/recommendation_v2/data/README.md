# 新版推荐数据

这里保存 `recommendation_v2` 自己生成和使用的数据，不修改旧推荐流程的数据。

- `dining_catalog/v1/`：严格包含 `Restaurants` 标记的餐厅商家及其原始类别统计。
- `category_catalog/v1/`：从餐厅真实类别生成的固定模型选择表和上下级关系。
- `business_facts/v1/`：2447家餐厅的统一基础事实、四档价格区间和字段覆盖情况。
- `review_index/v1/`：全部餐饮评论片段、稳定行号和一一对应的本地文字向量。
- `review_features/v1/`：14种特征的旧词表候选、意思相近候选、两路合并结果和真实评论抽查样例。
- `business_aspect_profiles/v1/`：500家餐厅的14项离线程度、证据充分程度、争议程度和代表性评论。方向直接继承训练时0到4刻度；大型SQLite文件由构建程序生成，不进入普通Git。

固定类别表不保存“用户可能说法”。大模型只能从 `selectable=true` 的真实类别中选择，程序负责检查并把上级类别展开成可执行的数据库条件。

商家基础事实中的类别仍是 Yelp 原始类别。评分和评论数量来自原始商家文件；预约、配送、外带、室外座位、儿童、多人、轮椅、带狗和五种停车方式来自原始商家属性。原始数据未提供明确真假时保存为空值，留给后续评论证据层补充，不在这一层猜测。

评论粗筛结果只表示“可能相关”，不能直接当成正负证据或商家分数。切分后的片段只用于查找；供后续判断和总结使用的是完整原始评论。全部片段向量保留后，还可以服务14种固定特征以外的用户问题。
