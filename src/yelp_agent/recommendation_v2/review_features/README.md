# 14种评论特征粗筛

这里完成的是“先找到可能相关的评论”，不是最终的正负判断和商家打分。

## 输入

- 2447家餐厅的统一商家基础事实，用来限定餐厅范围；
- 49.9万条餐厅完整原始评论；
- 旧版14种特征词表；
- 已切好的评论片段；
- 本地 `Qwen3-Embedding-0.6B` 文字向量模型。

## 两路怎么找

第一路扫描完整评论中的旧词语。旧词表中的正向词和负向词在这里合并，只要命中就作为“可能相关”；不会在这里把 `quiet` 当好评、把 `noisy` 当差评。

第二路把14种特征的两端含义写成完整句子。例如安静程度同时包含“安静、适合交谈”和“吵闹、需要喊着说话”。这些句子与全部评论片段向量比较，每家商户、每种特征保留最接近的少量完整评论编号。

片段只负责定位。两路合并后，供后续模型判断的是完整原始评论。

## 固定输出

- `keyword_candidate_reviews.parquet`：旧词语命中的完整评论；
- `keyword_candidate_aspects.parquet`：旧词语命中的“评论—特征”关系；
- `semantic_candidate_aspects.parquet`：意思相近路线命中的“评论—特征”关系；
- `candidate_reviews.parquet`：两路合并后去重的完整评论；
- `candidate_aspects.parquet`：两路合并后的“评论—特征”关系；
- `recall_audit_samples.json`：每个特征三种来源的真实评论抽查样例；
- 各层 `manifest.json`：输入校验值、输出校验值和数量。

最终关系表明确保存旧词语是否命中、命中了哪些词、意思相近路线是否命中、相近程度以及最接近的特征说明。相近程度只用于粗筛排序，不能直接当成正负、可信程度或商家得分。

当前真实结果是310,561条不同完整评论和929,826条“评论—特征”候选关系。抽查文件除了三种来源的最高分样例，还包含 `semantic_only_weak_tail`，专门展示意思路线最弱的尾部候选。尾部已经确认包含无关评论，所以这一步的结果必须再经过相关性细判断。

## 运行

在项目根目录执行：

```powershell
& '.\.venv\Scripts\python.exe' -m yelp_agent.recommendation_v2.review_features.pipeline `
  --model-path 'D:\models\Qwen3-Embedding-0.6B' `
  --python-executable 'D:\anaconda3\python.exe'
```

全量向量生成支持断点续跑。程序中断后重新执行同一条命令，会从已完整保存的数据块之后继续；来源和生成结果都没有变化时，已经完成的层会跳过。

## 这一步明确不做什么

- 不判断候选评论是否真的相关；
- 不判断正面、负面、强弱和适用条件；
- 不根据星级代替14种特征判断；
- 不计算商家0～100分；
- 不把粗筛结果直接用于最终推荐。

下一步应使用经过标注或蒸馏的小模型，对候选完整评论逐条判断“相关/不相关、方向、强弱和条件”，再按商家和特征聚合。
