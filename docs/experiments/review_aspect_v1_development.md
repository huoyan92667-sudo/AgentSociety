# Review Aspect V1：5000 用户开发集与规则反馈记录

## 当前边界

本阶段只使用预处理阶段选中的 5000 位用户及其 `139,402` 条历史评论，输入文件为 `data/processed/interactions.parquet`。尚未处理目标商家集合中的 `617,718` 条全量评论。

这样做的目的是先用较小开发集验证 Aspect 定义、句子切分、规则精度和 DeepSeek 审核流程。只有规则经过样本检查并冻结后，才允许构建全量商家评论产物。

## V1 固定 Aspect

当前保留 14 个较通用的 Aspect：食物质量、服务、性价比、安静程度、拥挤程度、排队时间、分量、停车、宠物友好、家庭友好、约会适合度、多人聚会适合度、辣度和清洁度。

`fatty_meat` 与 `lean_meat` 不进入固定 Aspect。此类低频、强场景细节以后由 Business-scoped Review RAG 根据用户当次问题检索原评论，而不是给所有商家预先打标签。

## 第一轮开发集结果

规则提取器 `1.0.0`、词表 `1` 的结果如下：

- 输入评论：139,402
- 至少命中一个 Aspect 的评论：63,205
- Aspect 记录：97,328
- `crowded` 记录：12,091
- 情感记录：positive 73,700，negative 23,454，mixed 174

每条记录保存评论、用户、商家、评论时间、Aspect、情感、置信度、原文证据及其精确字符位置。线上查询接口强制要求 `cutoff_time`，并且只返回严格早于该时间的记录。

## DeepSeek 小样本审核

审核输入只包含匿名句子和候选标签，不传入用户 ID、商家 ID、评论 ID、API Key 或 ground truth。输出必须通过严格 JSON Schema 校验；错误响应不会修改规则。

最初的 6 条样本请求因 DeepSeek V4 默认思考模式产生了较高开销：约 78.5 秒、9577 token。随后为审核任务单独配置：

- `thinking=disabled`
- JSON Object 输出模式
- `max_tokens=2000`
- 温度 0
- 单次超时 90 秒

优化后同一规模的 6 条样本耗时约 3.7 秒，输入 761 token、输出 624 token、总计 1385 token。3 条已有规则结果的 Aspect、情感和证据均获得 DeepSeek 认可；3 条未命中样本中得到两个候选短语：`generally good` 和 `very busy`。

## 扩大到 56 条审核

随后将审核扩大到 56 条，其中 28 条来自已有规则命中，28 条来自规则未命中。实验确认默认 thinking 会显著消耗输出 token：20 条试验中的两个批次都用满 2000 token 且没有生成最终正文。因此最终审核配置调整为：

- `thinking=disabled`
- `max_tokens=12000`（只是安全上限，正常完成 JSON 后立即停止）
- 每批 10 条
- 总样本 56 条

最终 56 条均完成审核。已有规则样本的 Aspect 正确率为 96.4%，情感正确率为 82.1%，证据支持率为 96.4%。结果包含 5 个漏检 Aspect、1 个错误 Aspect 和 4 个错误情感，说明 V1 当前最明显的薄弱点是局部否定、转折和比较对象，而不是 Aspect 大类本身。

DeepSeek 共给出 23 个原始规则建议，其中 1 个建议的证据不是输入句子的精确子串，验证器仅丢弃该建议并记录 `discarded_suggestion_count=1`，没有让改写或伪造证据进入规则。剩余 22 个候选也必须经过本地频率统计和语境抽样，不能自动写入词表。

关闭 thinking 的首轮 56 条审核实际消耗 12,035 token、API 总耗时约 32.9 秒。为补齐一个不合法批次又执行了两次单批重试，各约 2006 token；完整审核过程累计约 16,047 token。成功批次均写入缓存，重复运行不会再次计费。

## 规则反馈决定

大模型建议不会直接写入词表，必须经过本地出现次数统计、语境抽样和回归测试。

### 拒绝：`generally good`

该短语在开发集中出现 54 次，但本身没有说明“什么很好”。如果直接放入 `food_quality`，可能把服务、环境或购物体验误判为食物质量，因此本轮拒绝。

### 收窄后接受：`very busy`

原短语在开发集中出现 537 次。抽样发现它既可能表示餐厅拥挤，也可能出现在“忙碌的一天”或“繁忙街区”等无关语境中，因此不能直接加入。

词表 `2` 仅加入带商家语境的窄短语：

- `get very busy`
- `gets very busy`
- `restaurant was very busy`
- `place was very busy`

同时增加回归测试，证明“This place can get very busy”会命中 `crowded=negative`，而“I had a very busy day of meetings”不会命中。

## 第二轮开发集结果

规则提取器 `1.1.0`、词表 `2` 重建结果如下：

- 输入评论：139,402
- 至少命中一个 Aspect 的评论：63,257，比第一轮增加 52
- Aspect 记录：97,419，比第一轮增加 91
- `crowded` 记录：12,182，比第一轮增加 91
- 情感记录：positive 73,700，negative 23,545，mixed 174

新增规则共命中 100 条包含 `very busy` 的证据，其中部分评论也被已有拥挤规则命中，因此最终净增 91 条 Aspect 记录。新增证据中未发现 `busy day` 或 `busy part of town` 两类已知误判。

## 第三轮规则反馈与开发集结果

56 条审核后，对候选短语在 139,402 条开发集评论中统计频率并抽查语境。词表 `3`、提取器 `1.2.0` 接受以下通用规则：

- `reasonable prices`：性价比正面，开发集出现 597 次；
- `over priced`：性价比负面拼写变体，出现 428 次；
- `food was good` 与 `food was also good`：食物质量正面；
- `service is quick`：服务正面，出现 258 次；
- 停车正面改为 `has a parking lot`、`large parking lot`、`private parking lot`、`good parking options` 等有明确语境的短语。

单独的 `parking lot` 在开发集中出现 852 次，抽样同时包含“有免费停车场”“停车场满了”“不要停在那里”“在停车场吃饭”等正面、负面和中性语境，因此从正面词表删除。`snacks`、`find better`、`friendly`、`require you to drive there` 等建议也因语义不稳定而拒绝。

第三轮重建结果：

- 输入评论：139,402
- 至少命中一个 Aspect 的评论：64,096，比第二轮增加 839
- Aspect 记录：99,073，比第二轮增加 1,654
- `food_quality`：55,314，增加 1,101
- `price_value`：8,939，增加 1,040
- `service`：10,209，增加 248
- `parking`：556，减少 735 个宽泛命中
- 情感记录：positive 74,921，negative 23,976，mixed 176

停车记录减少是精度优先的主动收缩，不代表能力退化。规则测试同时证明“餐厅有大型停车场”能够命中，而“餐车停在停车场里”不会再被当作停车方便。

## 下一道阶段门

当前只能说明“开发集规则反馈闭环可以工作”，还不能说明 14 个 Aspect 已经达到最终质量。下一步应扩大但仍受控的 DeepSeek 审核样本，重点检查：

1. `crowded` 中 `packed` 等多义词的误判；
2. 规则命中样本的 Aspect、情感和证据准确率；
3. 未命中评论中是否存在高频、可复用且语义明确的新短语；
4. 每条候选规则的新增覆盖量和误判风险。

只有候选规则人工确认、测试通过、词表版本冻结后，才运行 617,718 条全量评论构建。

## 后续提升方向

规则版是可解释、可复现的第一版，后续可保持相同输出 Schema 并替换提取器：

- 本地分类模型：用于判断句子属于哪个 Aspect 以及正负情感，补充规则难以覆盖的表达；训练数据可来自人工确认后的规则样本和 DeepSeek 审核样本。
- Sentence Embedding：用于将未命中句子与 Aspect 原型做语义相似度匹配，发现不包含固定关键词但意思相近的表达。
- LLM Extractor：只处理规则与本地模型低置信度的句子，输出相同的结构化记录，以控制成本和延迟。
- Business-scoped Review RAG：保留原始评论级证据，在用户询问肉偏肥偏瘦、求婚氛围等临时细节时，只检索候选商家的截止时间前评论。

无论以后使用哪一种模型，都必须保留严格时间截断、证据原文、提取器版本、缓存指纹和失败回退。
